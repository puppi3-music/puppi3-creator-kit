How settings work

A site is one folder (setup makes it: kit/setup.sh <folder>). Its settings are in three kinds of file there:

  • site.env: the site itself (its address, name, time zone, which modules run). No secrets, so it's safe to keep with notes or in a private repo.
  • secrets/<stack>.env: each part's passwords and keys. Setup makes random passwords; the keys for outside services (each social network's app, Cloudflare, Search Console) are yours to add.
  • On Kubernetes, a few more: secrets/ghost-mail.env, and for a cloud, secrets/cloud.env, secrets/s3.env and cloud-<overlay>.env.

After a change, start the site again and the parts that use the setting are recreated:

kit/kit.sh <folder> up -d          # Docker Compose
k8s/up.sh <folder> <overlay>       # Kubernetes (local, eks, gke, ...)
Two exceptions

TinyIce's passwords and Ghost's mail on Compose are written once, by setup, into files of their own (data/icecast/tinyice-data/config.json, hashed, and data/ghost/ghost/config.production.json). Change those in TinyIce's admin page and in Ghost's config file.

A name in both site.env and a secrets file takes site.env's value. In the tables, setup asks means setup asked you for it, setup makes it that it's a random password made for you, setup fills it in that setup worked it out from your answers, and optional that the line starts commented out, with its default shown.

secrets/: one file per stack

Each stack's passwords and keys, in secrets/<stack>.env. Setup writes every file with random passwords; the keys for outside services (each network's app, Cloudflare, Search Console) are yours to add. Keep these files private: they're the only copy.
